A comment per manual step — five options

Nik, 2026-09-18: “manual steps sometimes require the user to enter something, or the user wants to leave a comment per step.” Two needs hide in that. One is reporting with a value — “done, but I named it billing-prod” — where the agent needs the detail to carry on correctly and today gets one bit. The other is qualifying or refusing — “no, use SQLite”, “blocked, GitHub will not let me” — which the card cannot express at all, because a step can only be ticked, never answered.

The thing to judge is attribution, not typing convenience. Ticking a step and typing the detail in the composer already works and costs the same one turn — so a per-step field earns its place only if it keeps the link between the sentence and the step, the way an offer's payload keeps its provenance. Each option below says what the agent receives.

  • Drawn in the card's real place: agent prose above, the composer below. Semantic tokens only, four themes.
  • The manual steps in every board are the same four, so the options differ only in what the row can do.
  • Not drawn: a “Done / Won't do” button pair with no free text. It answers the refusal half without a keyboard, and cannot carry a value at all — and Nik's words name a comment. It would also be a second control beside the toggle on every row, which req 2 (no padding) does not pay for.
