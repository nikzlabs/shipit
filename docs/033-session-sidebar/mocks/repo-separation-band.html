Variant 4 — the filled header band, in Claude Light and Claude Dark

Variant 4 gives each repo header a full-bleed tinted band, so the rail reads like a table with section headers. It has one property none of the other variants have: the repo header is position: sticky (SessionGroup.tsx:336), so whatever it looks like is what you stare at the entire time you scroll a long group. Every frame below is really scrollable and really sticky — scroll one and watch the header behave.

The Claude palettes are the hard case for this variant, because they are extremely flat. Measured against the sidebar rail (--color-bg-primary):

Two findings that decide this, both checkable:
1 · In Claude Dark, --color-border-primary is #2e2519 — byte-identical to --color-bg-tertiary. So a tertiary band with border-primary rules top and bottom has invisible rules: the band and its own edges are one color. Not a bug — it means option 4b is a clean solid block there and a block-with-edges in Claude Light, i.e. the two themes don't match. Rules have to come from --color-border-secondary if you want them in both.
2 · The current-session row already uses --color-bg-secondary (SessionGroup.tsx:431). So the band as specced is the exact same fill as the selected row — at 1.09:1 against the rail, in a palette this flat, the header and the selection become the same object. Any band that ships here has to sit at a different rank than the selection, not the same one.
3 · A translucent band on a sticky header is a bug, not a style choice. Every *-subtle token is rgba(), and this header is position: sticky — so session rows scroll through a tinted band instead of under it. Option 4c composites the tint over bg-primary with a double linear-gradient; option 4c-raw below is the naive version, left in so you can see it smear. This bites any accent- or hue-tinted band, so it applies to variant 5's spine idea too if that ever moves onto the header.

Why the band is worth the trouble: the stuck state

Scroll these two. Today's header is bg-primary — mechanically fine (nothing smears), but when it's stuck it looks exactly like the rows sliding underneath it, so the answer to "which repo am I in?" is a font-weight bump on a line that no longer looks pinned. A band makes the stuck header read as chrome instead of content. This is the argument for variant 4 that none of the other variants can make.
