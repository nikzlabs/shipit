docs/262 — the Plugins tab (right rail)

The plugin instrument panel lives as its own right-rail tab, beside Preview / Files / Issues — not in the chat column, whose PR card describes the work in flight. The tab is gated on plugin intent: any plugins: block shows it, including one that parses to zero valid repos — an invalid declaration must not erase its own warning surface. Urgency escapes the tab as a warn dot on the label (the existing Tab.badge slot, labeled "Plugins — attention required"); parse warnings, never-fetched, unavailable, collisions, and unmet needs all count. Services stay in Preview's services drawer (req 16 parity) with origin badges — this tab manages the environment: versions, refresh, credentials, hosts, errors. Invariant: one card per declared repo, always — simultaneous problems stack as rows under one header whose chip shows the worst state.

"Add key…" opens the existing Project Settings dialog on the consuming project's secret store — setProjectSettingsRepoUrl(consumerRepoUrl, "secrets"). That call selects the store /api/secrets writes to, so passing the plugin repo's URL would save the key in the wrong place. "Allow" posts to the existing browser-only POST /api/egress/hosts; "not allowed" is the agent container's truth (where the CLI runs), so the row names what it blocks.
