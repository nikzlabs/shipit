Mode & network — one composer control

Prototype for docs/285-network-mode-at-session-creation/requirements.md. Network containment is needed rarely, so it gets no new control: it joins the composer's existing permission-mode button, which becomes one flat menu holding both settings — same on desktop and mobile, for new sessions and running ones alike (reqs 5–7). The mode leaves the parameters menu, which removes a nesting level there (req 9).

Today — the four-step dance

Egress is plumbed at container creation, and the only control lives on a session that already exists. So the mode can only be corrected by restarting a session that has already started.

1
Start the session
Container boots on the workspace default.
2
Stop / wait
The turn must be idle before anything can restart.
3
Session settings → Network
Pick Open. “Pending · applies on next container start”.
4
Restart, then continue
Restart to apply now, re-attach, re-send.

1 · The control, at rest — no new footprint (req 5)

The trigger is today's permission-mode button, unchanged in the common case: Auto is a bare icon with no label. Network only appears on it when it is not the inherited default — the rare case pays the pixels, the common one pays none.

A network mode that tightens (Contained on an open workspace) shows the globe in the mode's own tint. Only a loosening turns the control amber — colouring the safe choice would train the eye to ignore it.

2 · The menu — flat, two sections, no drill-down

One popover, opened from that trigger. Both settings are visible at once and each is one tap away — the same body on desktop and mobile (req 6). The footer is the only difference between a session that has not started and one that is running.

7 · And what leaves Session settings (req 7)

The composer control now serves running sessions too, so the dialog's network radio group would be a second control over one session's egress. It goes. What remains there is the sandbox capability grants (docs/279), which are a different question — so for a non-sandbox session the sidebar's Session settings item has nothing left to open and disappears with it.

A sandbox's network access is a capability grant, not a containment mode — it stays here.

One consequence to accept. Today the mode control hides itself entirely for a harness that supports only Auto (Codex has nothing to toggle). Carrying network, it can no longer hide — it would render with a single, already-current mode row above the network section. That is the price of one control instead of two.
