Sidebar view switch — “Needs you”

A second sidebar view that drops the repo tree and lists only the sessions whose ball is in the user’s court. Attention is not a new signal — it is computeAttentionReason() (useAttentionInfo.ts), already the single source of truth for the amber rail, the tooltip and notifications. This view is a different projection of it.

All three questions below are independent: A where the switch lives · B what replaces the repo grouping · C how a row behaves when it stops needing you.

B · What replaces the repo grouping

Removing the repo headers leaves two holes: ordering (the tree gave the list its structure) and identity (which repo is this?). Identity is solved the same way in all three — the docs/254 repo color moves from the group header onto the row’s left edge, which is free because docs/187 put the attention marker on the right. Ordering is the real choice.

Notes carried by the drawings

Attention is not redefined. The view filters on computeAttentionReason() !== null — the function that already drives the amber rail, the row tooltip and notifications. A session is in the list for exactly the reason the tooltip already gives, so the two surfaces cannot disagree.

The amber rail is dropped inside the view. When every row needs attention, a per-row marker carries no information — it degrades to a texture. The reason word on the meta line does the work instead, and the right edge frees up.

Repo identity survives without repo headers as the docs/254 color on the row’s left edge plus a text chip. Left is free precisely because docs/187 chose the right edge for attention.

Parent/child nesting collapses. A spawned child that needs you is a first-class row here; the tree relationship is a property of the All view.

Ops, sandbox and hidden-repo sessions are ordinary rows. Their pinned groups exist to give repo-less sessions a home in a repo tree — a problem this view does not have.

Archived rows never appear — needsAttention is already gated on !isArchived today.
