Variant 3 revisited — containment with no rail to recess into

The first mock cheated. It floated the cards on an invented --color-bg-tertiary rail, but the real sidebar is --color-bg-primary (SessionSidebar.tsx:394) and the chat panel beside it is --color-bg-secondary (AppLayout.tsx:344). There is no third surface behind the groups. Cards drawn in bg-primary on a bg-primary rail are invisible — only their borders would show.

So every option below is rendered in app context: real rail, real chat panel to the right, so the surface hierarchy is visible rather than assumed. Same DOM in all six; only the wrapper class differs.

The constraint that decides it: in warm-light the sidebar is the lightest surface in the app, so a card cannot be lighter still. In dark it's the darkest, so a card cannot be darker. Any fill-based containment has to move in opposite directions per theme — which is exactly the bug the first mock hid. Outline- and edge-based containment sidesteps the problem entirely: a border works identically in both.
