# ShipIt v0.6.0

59 commits since v0.5.2. This release adds scheduled sessions, gives session containers access to an NVIDIA GPU, lets the agent compact its own context and change more settings through proposal cards, and makes rewind, restarts and merges more reliable.

## Read this before you update

- An "add host to the allowlist" card that is still pending when you update resolves as **stale** if you click it after the update. Ask the agent to post it again. New cards are not affected.
- When GPU access is off, a Compose service that asks for a GPU now starts on the CPU. Before, ShipIt refused the whole Compose file.

## Scheduled sessions

- ShipIt can start a session by itself on a schedule (for example, every weekday at 09:00), with a fixed target, settings and prompt. Ask the agent in chat to set one up: it posts a proposal card, and ShipIt saves the schedule only when you click **Confirm**.
- **Settings → Schedules** lists every schedule. There you can edit a schedule and use Run now, Pause, Resume, Stop and Delete. The session of each run has a banner that names its schedule.
- Runs have their own **Scheduled** view in the sidebar. A run with a question, an error or a manual step for you, and a schedule that could not start, show in **Needs you**.
- Each run keeps notes that later runs read. You can read the notes of any run in a read-only viewer. An agent in another session can read them only after you allow it.
- After ShipIt was down, it starts the latest run that is due and records the others as missed.

## GPU access

- **Settings → Advanced → GPU access** (off by default) gives the machine's NVIDIA GPU to the agent's container, to Compose services that ask for a GPU, and to containers that the agent starts. It works on WSL2 and on Linux. If Docker cannot give the GPU, the session starts without it and shows Docker's error.
- On WSL2, a Chrome that the agent starts can draw WebGL with the GPU.

## The agent

- The agent can compact its own context at a point it chooses (`shipit compact`) and name what the summary must keep.
- Settings proposal cards can now create and delete a role, and create and delete an MCP server. A card shows only the names of secret values; you type the values in Settings.
- The agent proposes a setting change or restarts its own container. It no longer writes these as manual steps for you.
- `shipit issue list` reads past the first 100 issues, adds `--search`, `--label` and `--limit`, and says when a list is not complete.
- `gh pr merge` no longer waits 20 seconds in a repository with no workflow files. `gh pr merge --auto` keeps waiting when GitHub says that a required check has not started.

## Reliability

- After a ShipIt restart (for example, an update), ShipIt follows a turn that continues in its session container and a turn that the agent CLI starts by itself. It saves and commits them as usual.
- A rewind is refused until the commit of the last turn is complete, so it cannot discard that turn's edits. **Recover recent rewind** ends when a new turn starts, so it cannot remove that turn.
- A rewind just after a session opens no longer fails with an `index.lock` error.
- New sessions start again for a repository that has no warm session, for example one not used for 30 days.
- The merge button works for a repository that moved to a new GitHub owner.
- When you turn off CI auto-fix, a fix turn that only waits is removed, and the PR card says so.
- An OpenCode compaction now ends its turn.
- A card posted in a turn that failed at sign-in is no longer saved twice.
- The release card now also appears for turns that ShipIt starts.
- A GitHub 5xx error now gives the request id and warns that a failed create can still be saved.

## Compose services and templates

- A Compose service that runs as the session's user now has a writable home directory (`HOME=/tmp`). This makes the previews of the Astro and Next.js templates start.
- `docker compose up` no longer fails on Docker Desktop.
- Hot reload in the project templates uses native file watching, not polling, so a preview uses less CPU.
- A running `docker compose up` no longer loses its files when a second service manager serves the same session.

## Interface

- The header shows the CPU load of the machine next to Docker memory.
- In the header, account names give way before the subscription meters, and the popover shows the reset time.
- Copy buttons work on plain HTTP addresses, for example a LAN address.
- **Needs you** also lists the sessions of hidden repositories.
- The **Configure** button on a missing-secret banner opens Project Settings → Secrets in every session.
- "Compact completed turns" is now **Collapse completed turns**. Your saved choice stays.
- Voice dictation lays out a message as lists and paragraphs when you say several points.

## Install and dependencies

- The local installer shows Docker's own error when `docker compose version` fails.
- Settings → Software Updates names `update.sh` for a manual update.
- Security fixes in dependencies: simple-git 4, proxy-addr, dompurify, ip-address, source-map-js and the MCP SDK.
