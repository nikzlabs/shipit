Three things about the diff region are load-bearing rather than styling. It scrolls inside a bounded region, so no length of value outgrows the dialog. Its lines are plain text, never markdown, so a heading or a link written into the value cannot render as ShipIt’s own chrome. And each changed line says which it is — colour and an aria-hidden glyph are the whole distinction on screen otherwise. A value carrying a bidirectional override or an invisible formatting character is refused before the card exists — a card that displays something other than what Apply writes fails the one test this refusal is. Past 10,000 characters a side, or 1,000 lines between the two versions, the refusal stands: that edit is the user’s own to make. Each changed line also carries an “Added:” / “Removed:” label for a reader that gets neither the colour nor the glyph.

Saved is not always live

A collection example, because this is where the distinction shows.

Applied · added registry.npmjs.org to the global allowlist Saved. Applies to sessions started from now on — running containers are unchanged. For a sandbox with network off it would say so instead: no restart grants a contained session the host.

A write can also land partly — changing the git identity is two separate commands, so the name can be saved and the email fail — or land with an outcome the writer cannot verify. Those are reported as themselves rather than squeezed into “applied” or “failed”. Reporting the case above as a plain “Applied” would tell the user the host is reachable now, which it is not. A global allowlist write does no live reload; only a session-scoped one does. The same split covers every write whose follow-up can fail after the value has landed — an update-channel change that then fails to check for updates, an MCP change whose per-session refresh is fire-and-forget.
