Sidebar view switch — “Needs you”

A second sidebar view that drops the repo tree and lists only the sessions whose ball is in the user’s court. Attention is not a new signal — it is computeAttentionReason() (useAttentionInfo.ts), already the single source of truth for the amber rail, the row tooltip and notifications (req 9).

Drawn as decided: header icon + count badge (req 4–5) · one flat list, stable order (req 6–7) · a row that stops needing you settles where it stands (req 8). Rejected alternatives are kept at thumbnail size at the foot.

Which glyph?

The first drawing used a warning circle. It is the wrong word twice over: WarningCircleIcon already appears about forty times across the client for genuine warnings, and “something is wrong” is not what the switch means — most of the list is an agent quietly waiting for you. Five candidates from the pack we already ship (@phosphor-icons/react), each drawn off the real path data, off state then on state. None of the five is used for anything else in the app.

The switch, at 3×

The switch carries the whole mode on its own (req 10), so its four states have to be told apart at 26 px. It is a pill, not an icon wearing a badge: glyph and count sit side by side, so the count can never sit on top of the glyph. The pressed state follows the house pattern for a toggled ghost button (IssuesViewer.tsx: glyph to fill weight, accent color, quiet chip behind it) instead of a saturated amber button, which the header has nowhere else. The glyph is ChatsIcon — see the board above for why.

Notes carried by the drawings

Attention is not redefined (req 9). The view filters on computeAttentionReason() !== null — the function that already drives the amber rail, the row tooltip and notifications. A session is in the list for exactly the reason the tooltip already gives, so the two surfaces cannot disagree, and no new state, store or server field is introduced.

Nothing sits above the list. An earlier draft put an amber “NEEDS YOU · 4 — Show all” strip under the header. It is cut. It costs about 28 px — the same height that ruled out the segmented control, so it gave back the one thing the icon was chosen to save — and everything on it was already on screen: the count is on the badge, the exit is a second click on the same icon, and every row states its own reason, which no row in the All view does. The switch is therefore the whole mode indicator, which is what the state board above has to earn.

The amber rail is dropped inside the view. When every row needs attention, a per-row marker carries no information — it degrades to a texture. The reason word on the meta line does the work instead, and the right edge frees up.

Repo identity survives without repo headers as the docs/254 color on the row’s left edge plus a text chip. Left is free precisely because docs/187 chose the right edge for attention.

Stability has two halves (req 7–8): the sort key never changes, and a row that stops qualifying holds its slot until the view is re-entered. Either one alone still lets the list move under the cursor.

Parent/child nesting collapses. A spawned child that needs you is a first-class row here; the tree relationship is a property of the All view.

Ops, sandbox and hidden-repo sessions are ordinary rows. Their pinned groups exist to give repo-less sessions a home in a repo tree — a problem this view does not have.

Archived rows never appear — needsAttention is already gated on !isArchived today.
