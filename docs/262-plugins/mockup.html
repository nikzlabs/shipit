B · Where plugin chips live — the PR card's collapsible panel, precisely (reqs 12, 15, 23, 24)

Anatomy matches PrLifecycleCard.tsx: a header bar that never collapses (left: PR state, title, diff, branch; right cluster: search · panel chevron · ⋯), and below it the collapsible panel (ChangedDocsStrip) that renders only when expanded — desktop defaults expanded, mobile collapsed, stored preference wins. Plugin chips are the panel's second row, under the docs/issue row. The header gains exactly one new element, and only conditionally: a warn pill beside the chevron when a plugin needs attention. Collapsed and quiet = no plugin trace, by design — near-static environment info doesn't earn permanent chrome; an actionable problem is never hidden by collapsing.

C · The plugin card (reqs 12, 15, 23, 24)

Opened from a plugin chip (B) — one card per declared repo. Header: repo name, source, ref @ exact running commit (req 15), Refresh (req 12). Body: what's used from it, then the needs list — every declared-but-unsatisfied credential (req 23) and host (req 24) with its grant affordance. Grants post to existing, browser-only endpoints; a satisfied card is quiet.

D · Plugin card states — degraded and collision (reqs 13, 15, 20)

Card states, not transcript cards. Degraded distinguishes a failed refresh (the prior complete generation stays active — req 15) from a repo that never fetched (the session degrades visibly and continues — req 13). A collision names its domain and the exact declaration fix (req 20). Each of these states also produces the B4 warn pill.

✕
