User-selectable roles — picker prototype

Prototype for docs/272-user-selectable-roles. A role is a starting point, selected before the session's first turn, and it never becomes a binding (req 3, req 4). It adds no control to the composer — it lives inside the model picker that is already there (req 5). The reviewer is never offered and never indicated (req 10, req 13).

Why the match rides the model chip. Req 13 asks ShipIt to indicate a match; req 5 forbids a fifth control. A chip that only ever reads is not a control, and the model chip is the one that already changes width with its content. State c is the whole of "does not warn": the role name disappears and nothing replaces it.

The rejected alternative: replacing the model name with the role name (Deep dive ▾). It reads better but hides the model behind a menu, and the model is the thing users check most often. Say if you would rather have it.

Roles sit above the models, in the same menu. Selecting one writes the harness, service, billing mode, model and reasoning level at once — the rows below then show that model as selected. Selecting a plain model instead clears the role name from the chip, because the combination is no longer the role's.

Unavailable roles stay, and say why (req 9). They cannot be selected and carry the reason and the fix. The reviewer role is absent (req 10) — this list is the whole reason that question mattered.

"No role" is not a fifth state. It clears the indicator only; it does not change the harness, model or reasoning. Nothing is put back (req 3).

Open question shown here: if two roles carry identical parameters, this prototype marks the first by name and stays silent about the other.

The Role panel.

This is the one place the design does grow. docs/260 states the root list stays four rows however far the catalogue grows — that promise is about catalogue growth, and this adds a fifth row for a new kind of setting, not for more models. It is the honest cost of req 13 and worth naming before it is built.

The alternative, if five rows is too many: fold Role into the Model row (Model · Deep dive) and put roles at the top of the Model panel, as the wide picker does. One rule for both widths, but a row labelled "Model" then also sets the harness and reasoning.
