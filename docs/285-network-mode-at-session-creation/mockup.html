Network mode at session creation

A prototype for docs/285-network-mode-at-session-creation/requirements.md. One control — the same Inherit / Contained / Open choice the session's own Session settings dialog already offers — moved onto the two surfaces that start a session, so the mode is chosen before the first turn instead of repaired after it.

Today — the four-step dance what this replaces

A new session's container is plumbed for egress at creation, and the only control lives on the session that already exists. So the mode can only be corrected by restarting a session that has already started.

1
Start the session
Container boots on the workspace default.
2
Stop / wait
The turn has to be idle before anything can restart.
3
Session settings → Network
Pick Open. “Pending · applies on next container start”.
4
Restart, then continue
Restart to apply now, re-attach, re-send.

A · New-session composer — wide (≥700px) recommended

A Network pill joins the composer's wide toolbar, inside the same clip group as the context dial, role, harness, model and reasoning controls (docs/260 req 1). It appears only while the session has not taken its first turn — after that, Session settings is the one control (req 6), so the two never compete. Default state reads the workspace setting and says so.
