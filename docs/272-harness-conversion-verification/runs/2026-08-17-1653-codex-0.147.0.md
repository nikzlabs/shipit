## Findings

1. **`wait` / `closeAgent` are unlisted collab tools.** The codex event
   handler passes any collab item's tool name through
   (`item.tool ?? "collab"`, `codex-event-handler.ts`), so tools beyond
   `spawnAgent` reach the transcript — but only `spawn_agent`/`spawnAgent`
   are in `CODEX_TOOL_NAMES`/the tool map. The `tool-map.test.ts` guard
   iterates the advertised list, so it structurally cannot see these —
   planning#337's "a tool the CLI uses that we never list at all" class.
   Benign today (generic row), but the inventory is provably incomplete.
   Recorded on planning#430.
2. **Conformance-capture provenance is one version stale.** The codex
   adapter tests' newest inline captures say "verified against codex-cli
   0.146.0"; the pin is 0.147.0. This is exactly the staleness signal the
   recipe's Step 3 defines; the recapture needs the Axis-3 tooling (or a
   credentialed environment) per the limitation above.
3. **Environmental**: the inner instance's UI entered a Vite full-reload
   loop (HMR websocket ECONNRESET through the proxy) after this turn and
   rendered a blank page until `shipit service restart dev` — consistent
   with the dogfooding skill's "health-check either side of every turn"
   warning. Server HTTP stayed healthy throughout; only the dev-server UI
   loop was affected.
