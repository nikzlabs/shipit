## Found here, fixed elsewhere

Defects this migration surfaced. **Not this feature's work** — listed as prose
rather than checkboxes so they don't hold this checklist open. The first three
are still outstanding.

- The `shipit` shim truncated piped stdout at 64 KiB — it exited without draining, so any agent running `shipit issue view … --json | jq` on a large issue silently got a cut-off document. Fixed on `main` in `9b031908` (`shim-exit.ts` flushes before exit); live in the deployed shim as of 2026-08-07.
- `trackers/linear/adapter.ts`'s `ISSUE_FIELDS` did not select `createdAt`, so an issue's creation date was unreadable — which req 9 requires. Fixed in the same commit; live in the deployed shim as of 2026-08-07.
- A GitHub **secondary rate limit** surfaces as *"the repository either does not exist or the connected GitHub credential cannot access it"* — the same message as a missing repo or a revoked token. It sends you to check the slug and the credential when the fix is to wait. `trackers/github/adapter.ts` should distinguish a throttle from an access failure (reads keep working during a throttle, and GitHub sends `Retry-After` / `x-ratelimit-*`), and ideally back off rather than surfacing an error at all. Hit during Pass B at ~870 writes in 15 minutes.
- The shim has no `label edit` or `label delete`, and `label create` refuses an existing name in any casing — so a label that exists with the wrong color or casing is permanently wrong. Hit here on three labels (see Migration above). Recorded in [docs/177](../177-agent-issue-writes/checklist.md).
- ShipIt's PR-merge flow **used to** post its "Resolved by ShipIt on merge of PR #N" comment repeatedly — `SHI-126` and `SHI-128` each carry 89 byte-identical copies, across 17 issues. **Already fixed**: every duplicate in the corpus was created between 2026-06-11 and 2026-06-13 (12, 208 and 8 extra copies respectively), none after, and `runMergeEffect` landed 2026-06-13 in `4ee77aa5` ("Fix duplicate issue-status cards on PR merge") — two days after the feature itself in `159fa3bd`. The migration surfaced three days of pre-fix history, not a live defect — worth recording because the raw counts read like an ongoing bug and sent one child session hunting before the dating was checked. That session confirmed the guard covers all three effects (status flip, resolved-by comment, progress comment) under independent persisted keys, and left behind a regression test at the real N=89 in `issue-lifecycle.test.ts`.
- `shipit issue list` on Linear queries `first: 100` with no pagination. It no longer blocks the export, which walks keys individually, but the limit stands.
- `CLAUDE.md` lines 306 and 329 describe behaviour docs/248 deleted — a bare `create` no longer defaults to Linear, and `issue:` should be written in the name form ([SHI-324](https://linear.app/shipit-ai/issue/SHI-324)). Wrong today, independent of the migration.
- Inline chat badges don't recognize the name form ([SHI-323](https://linear.app/shipit-ai/issue/SHI-323)) — landed.
