Use your OpenAI key for cleanup too?
Cleanup now runs on your Background work model. Your OpenAI key is stored for speech only, so adding it as a model provider lets it clean transcripts as well. It stays visible and removable under Model providers like any other credential.

What changed. The status line stops naming a provider ShipIt picked and names the user's own choice, linking to it — the old line described a decision the user could not see or change. The slow case says so plainly rather than letting a three-second pause look like a bug, and names the one thing that fixes it. The notice is the migration the design owes: the OpenAI voice key is not a model provider credential, so without this an install whose only key is that one loses working cleanup. Declining leaves cleanup unavailable and says so, rather than writing a Background work choice the user never made.

What changed. One row, in the install-wide view only. A dictation cleaned with no session open spends real money and today has nowhere to be recorded, because a usage row requires a session id. Why it is here. Background work is kept out of the dial by one field — sub_agent_id on the usage row — and the design removes the harness id that fills it. Without an explicit replacement, a pull-request description written by a direct call would count as a session turn, and this dial would show Haiku 4.5 and the background model's occupancy instead of the session's own. The prototype records the correct state so a regression is recognisable.
