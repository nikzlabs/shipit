Mobile new-session screen — where does the repository go?

On mobile, + New Session navigates to /{owner}/{repo}/new with a repo the app picked implicitly (current session's repo → active repo). The sidebar, which is where the desktop shows the repo group, is a closed drawer. Nothing on the screen names the repository.

Quick sessions do not have this problem: the overlay carries an explicit “New quick session in ⟨repo⟩” picker. Five options below, all drawn at 344 px with the real dark-theme tokens and the docs/254 repo colour (Cyan).

Historical: this is the prototype the 2026-08-09 choice was made from, kept as that record and deliberately not redrawn. On 2026-09-03 requirement 1 was rescoped to every viewport, so the chosen option B now ships on desktop too — same bar, with the picker as a centered card instead of a bottom sheet above 768 px.

Reading the options

  • A is the smallest diff and the weakest surface: the header is already the busiest 44 px on the phone, and a long owner/repo truncates against the status icons.
  • B is the only option that is both persistent and switchable, and it lands in a slot that is already empty on this route — the PR lifecycle card takes it over the moment the session graduates, so the handover is automatic.
  • C puts the answer next to the send button but competes with five controls that are already fighting for the same row on a 390 px screen.
  • D costs nothing permanent and reads at a glance, but only exists before the first message.
  • E asks the user to learn a colour. Good as a reinforcement of a named surface, not as the only signal.

Recommendation: B, with D as a free complement. B answers “which repo am I in?” for as long as the question is live and makes a wrong implicit default correctable in one tap; D makes the answer unmissable on arrival at no lasting cost. E’s colour rail can ride along on either, since the palette already exists from docs/254.

Not prototyped, deliberately: changing the implicit repo choice itself. That is a different question from showing it.
