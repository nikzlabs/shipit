# ShipIt v0.7.0

158 commits since v0.6.0. This release adds OpenCode 2 as a new agent, one-off schedules, Claude Haiku 5.5, a maximize button for the preview and `/persist` in the Files panel. Your messages now steer every turn, and messages between sessions go to an inbox. ShipIt compacts a large idle session before its prompt cache expires, and many fixes make merges, sign-ins, restarts and previews more reliable.

## Read this before you update

- The model picker shows only GPT-6 models from OpenAI. A session set to a GPT-5 model moves to a GPT-6 model on the same service and billing.
- A compaction that ShipIt starts by itself now runs only above 200K tokens. This is also true when **Compact the context** is ticked after a merge. Below 200K, only your own `/compact` compacts.
- When Claude runs in **Auto** mode, it no longer asks for your approval, also for `.git`, `.env` and similar paths.

## New

- **OpenCode 2** is a new agent, beside OpenCode 1, with the same sign-ins. OpenCode 1 does not change.
- **Claude Haiku 5.5** is in the model picker, for an Anthropic subscription and for an Anthropic API key. Claude Code is updated to 2.1.300.
- **One-off schedules**: a schedule can run once, at a date and time, and then not repeat.
- **Preview maximize**: a new button in the preview toolbar makes the preview fill the browser window.
- **`/persist` in the Files panel**: you can see the files in `/persist` and add them to chat.
- **MCP servers on a Compose service**: a plugin or a project's `shipit.yaml` can declare an MCP server that runs on one of its Compose services. The agent gets it only in that project's sessions.
- **Ops sessions** can read the chat of any session on the host, use their granted SSH destinations, and have `docker` and `journalctl` on local stacks.

## You steer every turn

- A message that you send while the agent works now reaches the current turn at once. This includes turns that ShipIt started, for example after a restart or a merge.
- **Stop** puts your queued messages back in the input box, in send order and with their attachments.
- Queued messages stay in their own session and show their attachments on every screen.
- After a merge, your choice for **Compact the context** stays with the session. You can also change it from the PR card menu.

## The agent

- When you tell the agent to compact its context, it does it itself. You do not type `/compact`.
- ShipIt compacts a large, idle session shortly before its prompt cache expires, so your next message costs less. After a ShipIt update, it starts the stopped container to do this, then stops it again.
- Messages and reports between sessions go to the recipient's **inbox**. The agent reads all unread messages with one command, not one turn for each.
- `shipit agent run` has no limit for each turn. It limits the number of runs in progress, so unattended work does not stop. Consults that start at the same time no longer fail, and a failed run says why.
- When a call waits for your approval, ShipIt alerts you. If nobody answers, the permission card says so and the agent is told.
- When an account reaches its limit and ShipIt moves to another account, the agent is told which sub-agents and background jobs stopped. Automatic wakes that every account refused start again at the stated reset.
- The agent is told when ShipIt does not push its commits and when a turn stopped its background jobs.
- A rewind forks the agent's own conversation at the rewind point. It no longer sends the whole chat again.
- Long prompts are priced at the vendor's long-prompt rate (Haiku 5.5, Gemini 3.1 Pro, Grok).

## Merges and pull requests

- `gh pr merge --auto` says what holds a waiting merge, and a GitHub read with no answer ends after 30 seconds.
- A merge that got no clear answer from GitHub is resolved at the end of its turn. Later merges on the session are no longer refused.
- After the agent merges its PR and opens a new one, ShipIt no longer marks the session as merged or shows a false "Not pushed" notice.
- A parent session can follow a child across several PRs, and its watch no longer replaces the child's own watch.
- **Sync with main** removes a stale `.git/index.lock` and tries again.
- A session stays out of **Recently resolved** while its agent works.

## Sign-ins

- The Claude and Codex sign-in refreshers renew tokens ahead of the sessions, report a revoked sign-in correctly, and no longer stop a turn in progress. A turn that a renewed sign-in cuts says so and continues.
- A sign-in that a restart interrupted is reset.

## Previews, services and the browser

- The preview no longer reloads when you switch to another session or to the **New session** page and back.
- New sessions open with their warm services running more often, and warm sessions stay current with the default branch.
- ShipIt reads Compose service status from Docker events, not from a poll every 5 seconds for each session. This uses much less CPU on the host.
- A stopped Compose stack gives back its Docker network, so previews no longer fail on Docker Desktop with "address pools have been fully subnetted".
- On Docker Desktop, a Compose service can mount `/persist`.
- On WSL2 with GPU access, the built-in browser draws WebGL on the GPU, and large texture uploads are fast.
- Screenshots of WebGL pages in the built-in browser no longer time out.
- `npx playwright test` works with a stable `@playwright/test`.
- `shipit service logs --lines N` returns N lines.
- Plugin commands start faster, get their stdin when it arrives, and stop when their caller goes away.

## Reliability and security

- After an orchestrator restart, the next turn uses the agent process that kept running. It no longer kills it and its background jobs.
- A stored agent conversation is never reset, so a Stop no longer loses a long session's context.
- An install that failed, or a dependency folder that came back incomplete, runs the install again.
- When Docker loses the Compose helper image, ShipIt recovers without a restart.
- Bug reports hide remotes and repository names in git output.
- Stale container image pins are updated, and CI now scans the images for known vulnerabilities.
- The VPS installer installs `cloudflared` from Cloudflare's apt repository, so you can upgrade it.
