# ShipIt v0.5.0

The largest release so far: 342 commits since v0.4.1. The agent gained a fifth harness, read and propose access to ShipIt's own settings, a status card it keeps at the end of every conversation, a product wiki it can answer from, and the ability to run commands on your servers — and the transcript, the preview pane and the orchestrator all got substantially faster.

## Antigravity is the fifth harness

Antigravity CLI joins Claude Code, Codex, OpenCode and Grok. Sign-in, event conversion, review support and tool-set behaviour are all wired; the sign-in panel now renders for every harness rather than only Claude, and a completed Antigravity OAuth login is no longer reported as a failure.

## The agent can read and propose settings

- The agent reads ShipIt's own settings (`shipit settings list` / `get`) instead of guessing at them, and reports a value it could not read honestly rather than as a default.
- It can **propose** a settings change as a card in the transcript; your click applies it. The card names its whole change, shows a long prose change as a diff, and tells the agent what you decided.
- The Settings dialog is now generated from one declaration per setting — every tab, every control, every Save. Along the way this fixed five misplaced rows, unsaveable panels, and messages pointing at tabs that no longer existed.
- Settings writes go through one shared layer that reports whether they actually landed; a half-landed change is reported as partial, and an unreadable credentials file fails closed instead of being overwritten with an empty store.

## A status card the agent maintains

Every conversation now ends with a card the agent keeps current: what the session is about, what only you can do by hand, and the follow-ups it offers. Manual steps can be ticked, commented on, or *answered* without being done ("no — use SQLite"), and the agent acts on the answer. Offers persist across turns until the agent retires them.

## SSH destinations

Grant a session a remote server and the agent can run commands on it — `ssh prod 'df -h'`, `scp`, `rsync`. The private key never enters the container; the orchestrator holds it, signs for it, and verifies the host key at the address before pinning it. Destinations are edited in place from Settings.

## A capability wiki

Ten pages shipped into every session describing ShipIt as a product — chat, the pull-request loop, previews and Compose services, plugins and MCP, settings and roles, issues and docs, repositories and sandboxes, deploying, backup and moving an installation, and a symptom-indexed troubleshooting page. The agent answers "can ShipIt do X?" from these instead of improvising.

## Faster, quieter UI

- Every turn but the newest collapses to the request and the reply, and rows render 20 at a time — long transcripts load and scroll without stalling.
- Two multi-second UI freezes are gone: quadratic syntax-highlight auto-detection, and the Docs tab's O(u²·n) grouping.
- Idle sessions no longer burn a quarter of a core; always-on animations step at 10 Hz, and spinners animate smoothly at lower cost.
- Each preview origin gets its own renderer process, and the "Preview unreachable" banner is gone — the proxy absorbs the connect wait instead of a health poll gating the iframe.

## Sessions, memory and containers

- ShipIt now rations by **memory** rather than a container count: idle previews keep running, and a session is only reclaimed when ShipIt is genuinely over budget.
- A merged session compacts its context before continuing, so the next piece of work starts clean.
- Session workers can no longer starve the orchestrator of CPU, Compose stacks that survived a restart are reaped, agent CLIs are killed as a whole process tree, and `docker-init` runs as PID 1 so orphans are reaped.
- Broken workspaces stay visible in the sidebar and are re-evaluated when you open the session, instead of quietly disappearing.

## Background work without a harness

Voice cleanup, session naming and other background tasks now run as direct provider calls on a dedicated executor, under a deadline the orchestrator enforces. Gemini joins the vendor catalogue. Background work says *why* a pin cannot run instead of blaming the credential, and autonomous work continues across a quota wall instead of waiting for a human.

## Chat, composer and navigation

- Chat search opens with Ctrl+F, from the transcript as well as the composer.
- Paste 2,000+ characters and the composer turns it into a file attachment; a refused send keeps its text and its attachments; attachments can be sent alone.
- `/goal` works natively on Claude Code, Codex and Grok, with a goal chip in the UI.
- Work that belongs in another repository is proposed as a one-click card.
- A daily update check surfaces as a dismissible banner.
- Repo search ranks your personal repos first and includes organization repos.

## Models

GPT-6 Astra, Fable 5.1, DeepSeek V4.1 Flash, ChatGPT subscription access through OpenCode, and GPT models running on the OpenCode harness. Image input is gated per model rather than assumed for every routed model, and Claude Code gets the real window for 1M models it does not recognise.

## Release and pull-request tooling

- Release notes are now agent-authored — this file is the first one published that way.
- `shipit release prepare` refuses a wrong-base or dead release PR instead of reporting success.
- The `gh` shim honours `-L/--limit`, refuses unknown `--state` and meaningless `--repo`, says when the PR it reprints is **merged**, and no longer reports a failed GitHub read as an empty repository.
- A branch left ahead of its remote is healed instead of holding the merge forever; a rejected push's divergence is measured rather than guessed.
- Merges are attributed for every path, not only managed auto-merge.

## Under the hood

Pinned agent CLIs and dependencies updated throughout; the full lint is no longer cached (the cache hid cross-file rule violations) and its heap cap is measured per environment; the Vitest worker pool is capped so a local run cannot take the instance down with it.
