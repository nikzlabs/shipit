# 250 — Agent session rename: requirements

The design that implements these requirements will be in `plan.md` (not yet written — this feature still has open questions).

Today a session's title is decided once, from the first message, and never changes again on its own. A session that goes on to do several rounds of work keeps a name describing only its first PR, so the sidebar stops describing what the session is actually about.

1. A session's title reflects the work the session has actually done, not only the work it started with.

2. The agent can change the title of the session it is running in.

3. The agent can only rename its own session — renaming somebody else's session is not something it can do.

4. If the user has ever renamed the session by hand, the agent's renames are ignored from then on. The user's chosen name is final and nothing overwrites it.

5. Nothing about renaming requires the user to do anything. A session the user never renames stays named sensibly on its own.

## Open questions

- **When does the agent rename?** The agent has to decide when the title has gone stale, and that judgement is the part most likely to just not happen.
  - (a) *Whenever the agent judges the title no longer fits* — most flexible, but relies on the agent remembering, every turn, to consider it.
  - (b) *Only at PR boundaries* — the agent is told to reconsider the title when it opens a PR, which is already a moment it stops and writes a summary of the work. Fewer chances to fire, but they're the chances that matter, and it attaches to an instruction the agent already reliably follows. **Recommended.**
  - (c) *Not the agent's call at all* — ShipIt re-titles automatically once a session opens its second PR, from the PR titles it already tracks. No reliance on the agent at all, but the trigger is coarse: it can't retitle a session doing lots of different work under one PR.

- **What counts as "the user renamed it"?** Requirement 4 is clear about a rename typed into the sidebar. Less clear are the titles a session can be *born* with: a title taken from the issue the session was started from (a human wrote that issue), and a title a parent agent chose when spawning a child session.
  - (a) *Only a sidebar rename locks the title* — issue-derived and agent-chosen starting titles stay replaceable. **Recommended**: an issue title describes the task the session was given, which is exactly the thing that goes stale as the session does more.
  - (b) *Any title not generated by ShipIt's automatic naming locks it* — safest reading of "the user chose this", but it means a session started from an issue can never be retitled, which is the common case this feature exists for.

- **Does the automatic naming at session start also respect these rules?** Today ShipIt names a session automatically a few moments after the first message, and that write lands late enough to overwrite a rename that happened in between.
  - (a) *Yes — the automatic namer never overwrites a title the user or the agent set.* **Recommended**; without this, a rename early in a long first turn silently disappears.
  - (b) *No — leave the automatic namer as it is*, and accept that an early rename can be clobbered.

- **Does renaming a session ever change its branch name?** ShipIt's automatic naming today renames both the title and the git branch.
  - (a) *No — renaming only ever changes the title the user sees.* **Recommended**: by the time the agent wants to rename, a PR usually exists on that branch, and renaming the branch underneath it would strand the PR.
  - (b) *Yes, while no PR exists yet* — keeps title and branch consistent for early renames, at the cost of a rule the user has to know.

- **Does the user see that the agent renamed the session?** The sidebar entry changing name is the only signal by default.
  - (a) *No separate notice* — the new name in the sidebar is the whole story. **Recommended**: a rename is not something the user needs to act on.
  - (b) *A line in the chat transcript* — makes the change explainable after the fact ("why is this session called that?"), at the cost of transcript noise on something minor.
