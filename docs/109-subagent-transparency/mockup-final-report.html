Subagent final report — formatting prototype

Four cases, current rendering on the left and the proposal on the right. The report is the one part of the card the reader actually reads, and today it is undifferentiated body text glued to the bottom of the card — indistinguishable from the parent agent's own prose, at full transcript width, with the CLI's accounting footer dumped raw underneath.

Case 1 — Backgrounded agent (the screenshot)

A run_in_background Task returns a launch acknowledgement, not a report. It is addressed to the agent and explicitly says "never quote any part of it" — yet the card prints it verbatim under FINAL REPORT and stamps the header done while the subagent is still running. This is a content bug wearing a formatting bug's clothes: the fix is to recognise the acknowledgement and not render it as a report at all.

Case 2 — An ordinary report

The core formatting change. The report gets a labelled panel so it reads as quoted output from another agent rather than as the parent's own voice; a measure cap (78ch) so it stops running the full width of the transcript; a flattened heading scale so a subagent's # can't out-shout the conversation it's nested in; and the CLI's accounting footer parsed into chips on the header instead of a raw key: value blob under the text.

Case 3 — A long report

Three parallel subagents each returning 60 lines buries the parent transcript. Clamp past ~10 lines with a fade; the header chips still say how big it is, so nothing is hidden silently. Shipped behaviour: the button opens a modal rather than expanding in place — which is what lets the transcript carry only the clamped head and fetch the rest on the click (requirements.md reqs 7–8).

Findings

runCommitAndPr is reachable from four places in turn-executor.ts. Three of them previously ended at tryDrain() alone, which commits only when something is queued.

  • Clean end — streaming agent_result / non-streaming done. Committed correctly.
  • Streaming abnormal exit — done with no agent_result. Crash, OOM kill, SIGTERM from a container restart.
  • Adapter-level error — onError, where a dispatched crash lands via dispatched-turn.ts.
  • Failed auth heal — the recovery path re-runs the turn but never commits the partial tree.

The memoisation on runCommitAndPr is what makes calling it unconditionally from all four safe: a duplicate call is a no-op rather than a second GitHub round-trip.

Guard tests: turn-crash-commit.test.ts and turn-drain-commit-ordering.test.ts cover paths 1–3. Path 4 has no test.

Case 4 — A failed subagent

Today the error body is a red-tinted box that reuses the report's font size, so a stack trace wraps as prose. Proposed: same panel shell in the error colour, monospace body, and the header carries the failure instead of a second label.

What this changes, in order of how much it matters
  • 1. The backgrounded-launch acknowledgement stops being rendered as a report, and the header stops claiming done for an agent that is still running. Content fix, not cosmetic.
  • 2. The report gets a panel — label row, border, faint surface — so it reads as another agent's output rather than as the parent's own prose.
  • 3. The accounting footer becomes chips (duration / tools / tokens) on the header; the agentId is dropped from view entirely since it is internal.
  • 4. Typography: 13.5px / 1.6, a 78ch measure, flattened headings with an accent tick, tightened lists, real <pre> and table styling.
  • 5. Long reports clamp at ~10 lines with a fade, and the full report opens in a modal.

Deltas between this mockup and what shipped. Two, both deliberate. (a) The expand opens a modal rather than expanding in place, so the transcript can carry only the clamped head and fetch the rest on the click — that payload saving is requirement 8, and it is the reason the report left docs/244's ship-whole exemption set. (b) The report panel's body is an opaque surface (--color-bg-primary) rather than the translucent white used above: the clamp's fade has to blend into it exactly, and a translucent panel's effective colour depends on whatever is behind it, which no single gradient stop can match across fourteen themes.
