# Run — Antigravity 1.1.27, account mode (2026-09-14)

A follow-up to [the 10:50 run](./2026-09-14-1050-antigravity-1.1.27.md), which
ended **PARTIAL** with three named gaps. This run closes all three. It found no
defect in the harness; it did correct a *belief* the first run left standing —
that the subagent surface merely wanted a better prompt.

## Gap 1 — the subagent surface: measured, and it cannot be driven

The first run asked for a subagent in the tour's step 7 and got a shell command
twice, which reads as prompt luck. It is not.

A prompt that names the tools and forbids the shell
([`subagent-prompt.txt`](../../301-antigravity-harness/probes/subagent-prompt.txt))
makes the model say so outright
([`subagent.ndjson`](../../301-antigravity-harness/probes/subagent.ndjson), exit
0, 11 s): *"I don't have access to the `define_subagent` or `invoke_subagent`
tools in my current environment."*

A model's account of its own toolset is a claim, so the answer comes off the
wire instead. `GOOGLE_GEMINI_BASE_URL` is redirected at
[`recorder.js`](../../301-antigravity-harness/probes/recorder.js) and the
outgoing `streamGenerateContent` body is read
([`tool-declarations.sh`](../../301-antigravity-harness/probes/tool-declarations.sh),
reproducible offline and against no quota — the recorder answers itself).

**The count was already on record and nobody had read it as an answer to this.**
The docs/301 tools-off probe of 2026-09-13
([`tools-off-1127.json`](../../301-antigravity-harness/probes/tools-off-1127.json))
captured the same **11** names, as the negative control for a different
question — *can anything empty this CLI's tool set?* — and its own README says
so. This run reproduces that number a day later, adds the configuration that
moves it, and draws the conclusion the earlier capture had sitting in it:

| Spawn | `init.tools` says | `tools[].functionDeclarations` carries |
|---|---|---|
| plain headless | 57 | **11** |
| + one stdio MCP server | 57 | **14** (`call_mcp_tool`, `list_resources`, `read_resource`) |

The 11 are `find_by_name`, `generate_image`, `grep_search`, `list_dir`,
`manage_task`, `read_url_content`, `replace_file_content`, `run_command`,
`search_web`, `view_file`, `write_to_file`. Every name and both byte counts are
in [`tool-declarations.json`](../../301-antigravity-harness/probes/tool-declarations.json).

**So `init.tools` is the CLI's catalogue, not the model's toolset**, and 43 of
the 57 are never offered in either configuration: the whole subagent family
(`invoke_subagent`, `define_subagent`, `browser_subagent`, `manage_subagents`),
every `browser_*`, the `ask_*` family, `command_status`, `send_command_input`,
`sed_file`, `multi_replace_file_content`, `notebook_edit`, `schedule`, `finish`.

Three consequences, and the first is the one that matters:

- The subagent surface is **structurally** undrivable headless, in the same
  class as `ask_permission` — not an untaken measurement. This is the honest
  version of the first run's "no observed driver".
- It retro-explains the `ask_question` capture: the model echoed the question in
  prose because it was never given the tool.
- Nine of the 18 names in `ANTIGRAVITY_TRANSCRIPT_TOOL_NAMES` cannot arrive on
  1.1.27. The map stays a superset deliberately — it costs nothing, and a later
  version that declares them renders a named card instead of a raw tool name.

**The side call, with its purpose now read rather than inferred.** The
2026-09-13 endpoint-redirect capture already recorded a second, per-turn call on
`gemini-3.1-flash-lite-preview` that ShipIt never selects. This run reads its
body: 819 bytes, **no** `tools` key, and a system instruction that is a
conversation-title generator. The stream's `usage` covers only the main
conversation, so the call stays invisible to the harness's token accounting —
small and fixed-size, but on a model the user did not choose.

## Gap 2 — Step 4 in full, on the ACCOUNT route

The dogfood inner instance, a real Google account
(`route=account:acct_bb68a5f5…`, `billingMode: "sub"`, `costUsd: 0`),
`gemini-3.1-pro-preview` at effort high, against
`nicolasalt-shipit/todo-list`. The service log confirms the shape the 10:50 run
fixed: `--add-dir <session workspace>`, and
`Google account token on disk — env credentials scrubbed so it cannot be
out-preferred`.

Two serial turns: the recipe's tour prompt, then one turn that asks for a
directory listing (the tour's own steps never force `list_dir`). Asserted on
persisted history, then on the UI, then on the UI again after a reload.

| Surface | CLI tool | Transcript | UI card |
|---|---|---|---|
| File read | `view_file` | `Read`, `package.json`, `120 lines, 3862 bytes` | `Read package.json` |
| File write | `write_to_file` | `Write`, correct `file_path` | path + **no changes** |
| File edit | `replace_file_content` | `Edit`, correct `file_path` | path + **no changes** |
| Shell | `run_command` | `Bash`, stdout `conversion-probe` | `echo conversion-probe` |
| Search | `grep_search` | `Grep`, `pattern` + `path` | `Grep conversion-probe` |
| Directory | `list_dir` | `Glob`, real listing | `Glob` |
| Task list | — | no driver | — |

**Reload.** The accessibility snapshot taken after `location` reload is
**identical, line for line**, to the one taken before it, once element refs are
stripped — 236 lines each. Rehydration from persisted history loses no card.

The Write and Edit cards render as a path plus **"no changes"**. That is the
first run's known limitation seen from the UI side rather than inferred from the
stream: 1.1.27 puts only `TargetFile` in `tool_info.parameters`, so there is no
body and no diff to render. Upstream, not this branch.

**One environment caveat, and it is the dogfood's, not the harness's.** The
first tour turn read `/workspace/package.json` and wrote `/workspace/probe-note.md`
— ShipIt's **own** checkout — although the spawn's cwd and `--add-dir` both named
the session workspace. `prompts/skeleton.md` tells every agent *"You are running
inside a Docker container. The workspace is at /workspace"*, which is true in a
session container and false in local mode, where the clone lives at
`/workspace/sessions/<id>/workspace`. The model followed the prompt over its own
cwd. The stray file was removed; the second turn, told to use its cwd, addressed
the session workspace correctly. Nothing here is Antigravity-specific — any
harness can act on that line in the dogfood.

## Gap 3 — the negative control

The 10:50 run recorded its own control as weaker than the recipe asks for: the
vocabulary guard compared two constants, so it could not have caught a
fabricated name arriving in a *capture*. There is now a checker that reads the
committed capture (`antigravity-tool-normalizer.test.ts`), and a control that
feeds it the same bytes with one tool name replaced by `TaskCreateV2` and
asserts it goes red. The checker is verified to be able to fail.
